# Medical History (Module E)

`patient_history_entries` (clinic-scoped). Categories: `condition`, `chronic_condition`, `previous_illness`, `surgery`, `hospitalization`, `family_history`, `immunization`, `lifestyle`. Fields: title, status (`active|resolved|inactive|entered_in_error`), code, description, onset/resolved/event dates (past, resolved ≥ onset), relative (**required** for family history), age at diagnosis, provider, notes, **source** (`patient_reported|caregiver_reported|clinic_recorded|imported|clinician_verified`), **verificationStatus** (`unverified|verified`), recordedBy/At, lastReviewedAt, version.

Rules: requires `history.view/manage` (doctors; nurses view only; **receptionists, admins and accountants have no access**). Creating/updating needs a **granted, unexpired `data_processing` consent** (409 once revoked). Only a **doctor** can verify (`verify: true` → source `clinician_verified`); the client can never set that source directly. Any content change resets verification to `unverified` and stores the old version in `patient_record_revisions`; nothing is silently overwritten and nothing is deleted (wrong entries become `entered_in_error`). Reads are audited. The system never suggests diagnoses.
