## How to read this

* **Resource completeness** — every locale has all 116 keys with the same placeholders as English. This measures the *resource files*, **not the product**.
* **Product coverage** — only the screens/strings listed in `ARCHITECTURE_AND_DATA_MODEL.md` §4 use the resources (authentication and status screens, validation and sign-in failure messages, navigation labels, status words, design-system texts, language menu). Most screen bodies are still English (see `LOCALIZATION_AUDIT.md`).
* **Quality** — Arabic, Hindi and Tamil are **machine-assisted starter translations**. They have not been reviewed by a native speaker or professional translator, are not certified, and must not be used for legal, clinical or consent wording. Gender, formality, regional wording and terminology (e.g. medical terms) need human review before release.
* Fallback: a missing translation shows the English text, never a key.

## Review workflow (proposed)
1. Reviewers edit the table in `tool/gen_arb.py` (one row per key, four columns).
2. `python3 tool/gen_arb.py && flutter gen-l10n` regenerates the ARB and Dart files.
3. `dart run tool/l10n_report.dart --check` must pass; native-speaker sign-off is recorded in the pull request.
