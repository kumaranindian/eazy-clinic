# Technical Debt and Known Limitations

| ID | Item | Impact | Plan |
|---|---|---|---|
| TD-01 | Firebase Admin SDK for Dart is not an official Google product; options must be evaluated (community package vs `googleapis` REST). Phase 0 has no Firebase dependency. | Blocks Phase 1 | **Resolved in Phase 1** (ADR 012): in-house RS256 verification + Identity Toolkit/Firestore REST. Not yet run against live Google services (TD-17). |
| TD-02 | Flutter 3.32.8 / Dart 3.8.1 are over a year old. `DropdownButtonFormField` uses `value:` (deprecated in newer Flutter in favour of `initialValue`). | Future upgrade churn | Decide upgrade before Phase 1; update `EcDropdown`. |
| TD-03 | Logo is raster with opaque white background; icon crop is derived from it. No transparent/vector master; no dark-mode variant; no Android adaptive icon (foreground/background layers). | Visual polish | Obtain vector master; regenerate assets with `scripts/sync_brand_assets.sh`. |
| TD-04 | Fonts and brand assets are duplicated (repo-level `assets/` and inside `design_system`), kept in sync by script. | Drift risk | Keep script; consider making `design_system/assets` the single source. |
| TD-05 | Three app shells duplicate ~100 lines of bootstrap (main, router provider, config provider). | Duplication | **Partly resolved** (ADR 013): `packages/app_core` holds auth. `main.dart`/router/home per app still repeat ~60 lines; extract a shared bootstrap later. |
| TD-06 | No CI. `scripts/check_all.sh` runs format, analyze and tests locally. | Regressions | Still open (not done in Phase 1): add GitHub Actions running `scripts/check_all.sh`. |
| TD-07 | One transient Android Gradle failure was observed (not diagnosed). Docker image build and Firebase CLI were not exercised. | Unknown | Verify in CI; build the Docker image in Phase 1. |
| TD-08 | Backend: unmatched HTTP methods return 404 (not 405) because of `shelf_router` defaults; no rate limiting; no graceful in-flight request drain beyond `server.close`. | Minor | Auth rate limiting done (TD-16); 405 if needed. |
| TD-09 | Web build warns that `CupertinoIcons` font is not found (we deliberately did not add `cupertino_icons`). | Cosmetic warning | Ignore unless Cupertino icons are used. |
| TD-10 | UI is verified by widget tests and one reviewed gallery screenshot; the web logo render was **not** visually confirmed in a browser (headless screenshot tooling was unreliable). Asset bundling and proportions are covered by tests. | Low | Confirm manually when running `flutter run -d chrome`. |
| TD-11 | Light theme only; no dark mode or localization (English only). India market will need Hindi/regional languages. | Product | Plan i18n in Phase 1 (use `intl`/ARB). |
| TD-12 | Accessibility checked by design (contrast, 48dp targets, semantics on key widgets) but no automated a11y audit yet. | Compliance | Add in Phase 11. |
| TD-13 | Contrast: white on brand red #E92335 ≈ 4.4:1 (< 4.5:1 AA for normal text); Medical Blue on white ≈ 4.5:1. Brand colours are mandated, so this needs a design decision (e.g. use 18 sp+ bold on red, or a slightly darker red for text/buttons). | Accessibility | Decide in Phase 1 design review; audit in Phase 11. |
| TD-14 | Revocation/disabled check calls Identity Toolkit on every authenticated request (latency, quota). | Cost/latency at scale | Add a short per-uid cache (e.g. 15–30 s) once measured; keep immediate checks for sensitive operations. |
| TD-15 | Firestore emulator tests exist (rules + store); the Auth emulator is not used (unsigned tokens), so token verification and Identity Toolkit calls are tested with doubles, a generated RSA key and a one-off openssl certificate check (not a committed test). | Identity Toolkit request shapes unverified | Test against the Auth emulator or a dev project; commit the openssl check as a fixture-based test. |
| TD-16 | Rate limiter is per instance and in memory; client address depends on `TRUST_FORWARDED_FOR`. | Weaker limits with several instances | Shared limiter (Firestore/Redis) before production; add per-account login throttling (Firebase already throttles sign-in). |
| TD-17 | **Not verified against live services:** Firebase sign-in/registration/reset, Google signing-key fetch, Identity Toolkit REST calls (Firestore REST **is** verified on the emulator). | Possible integration defects | Run the manual checklist in `docs/authentication/AUTHENTICATION_WORKFLOWS.md` §7 on the dev project before Phase 2 merges. |
| TD-18 | Android builds (doctor, patient) could not be run in this environment: the Android SDK download is blocked by the sandbox proxy. `firebase_auth` raises the Android `minSdk` requirement (verify `flutter.minSdkVersion` ≥ 23 and Gradle sync). | Unverified Android build | Build both APKs in CI/dev machine. |
| TD-19 | Terms of Service / Privacy Policy acknowledgement is a checkbox with no linked documents or recorded consent version. | Compliance (DPDP consent record) | Provide documents and store accepted version/timestamp (Phase 4 consent). |
| TD-20 | No MFA enforcement, App Check, device/session list, or e-mail-change/re-authentication flows. `platformRole` has no admin tooling (set manually). | Security hardening | Phase 3 (staff/roles) and Phase 11. |
| TD-21 | Until Phase 2/3, Clinic Web and Doctor admit only accounts with a manually assigned `platformRole`/membership, so staff cannot yet enter those apps. | Expected | Phases 2–3. |
| TD-22 | No API to grant/revoke `platformRole` (manage platform administrators); first Super Admin and support admins are set by hand in the console. No MFA requirement for platform roles. | Operational/security gap | Dedicated Super-Admin-only endpoint with audit + MFA/re-authentication (Phase 3 or a security hardening pass). |
| TD-23 | Membership resolution queries Firestore on every authenticated request; entitlements and the revocation lookup add reads. | Latency/cost | Short per-uid cache with explicit invalidation on membership/tenant changes. |
| TD-24 | Platform dashboard issues ~20 count queries per load; search is name-prefix only. | Cost at scale | Maintain counters (transactional increments) and a search index. |
| TD-25 | Firestore indexes (16) are defined but not deployed or exercised (the emulator does not enforce them). Combined audit filters are rejected for lack of composite indexes. | Missing-index errors in staging | Deploy and verify in the dev project before Phase 3 merges. |
| TD-26 | No scheduled job: expired subscriptions are *evaluated* but not persisted as `expired`; no reminder/e-mail notifications. | Reporting drift | Daily job + notifications in Phase 10. |
| TD-27 | Tenant `slug` is reserved but unused; no tenant configuration beyond `configurationVersion`. | – | Clinic setup module. |
